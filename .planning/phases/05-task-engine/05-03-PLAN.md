Frontend patterns established:
- SSR data loading: +page.server.ts with PageServerLoad, fetch from /api/* with cookie forwarding
- Client-side mutations: api() utility for POST/PATCH/DELETE, then invalidateAll()
- URL-synced filters: goto() with replaceState:true, read from $page.url.searchParams
- Svelte 5 runes: $state, $derived, $props, $effect throughout
- TailwindCSS v4: Complete class strings in Record<string,string> lookups, never interpolated

API response shapes (from 05-01, 05-02):
- GET /api/tasks -> { data: TaskListItemDto[], meta: { total, page, limit, totalPages } }
- GET /api/tasks/:id -> TaskResponseDto with relations, checklistProgress, isBlocked
- PATCH /api/tasks/:id/status -> { status: TaskStatus } body -> updated TaskResponseDto
- GET /api/tasks/:taskId/checklist -> ChecklistItemDto[]
- GET /api/tasks/:taskId/dependencies -> { blockedBy: [...], blocking: [...] }
- GET /api/tasks/:taskId/comments?page&limit -> { data: CommentDto[], meta }
- GET /api/tasks/:id/activity?page&limit -> { data: ActivityEntryDto[], meta }
