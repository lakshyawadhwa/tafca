# Phase 5 — UI Design Contract

> Visual and interaction contract for the Task Engine phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker. **Extends** the Phase 3 design system and Phase 4 component library — all tokens (spacing, typography, color, component APIs) carry forward unchanged.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (SvelteKit -- shadcn not applicable) |
| Preset | not applicable |
| Component library | Custom Svelte 5 components with TailwindCSS (Phase 3 + 4 library) |
| Icon library | Lucide (lucide-svelte) |
| Font | Inter via CDN (Google Fonts), weights 400, 600 |

**Inherited from:** Phase 3 UI-SPEC (03-UI-SPEC.md), extended by Phase 4 (04-UI-SPEC.md). No changes to the design system foundation.

## Spacing Scale

Inherited from Phase 3. No changes to base scale.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, badge padding-x |
| sm | 8px | Compact element spacing, input padding-y, table cell padding |
| md | 16px | Default element spacing, card padding, input padding-x |
| lg | 24px | Section padding, sidebar item padding-x, modal padding |
| xl | 32px | Layout gaps, sidebar padding-y, form group spacing |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Phase 5 exceptions:
- Kanban column gap: 16px (`gap-4`) between status columns
- Kanban card inner padding: 12px (`p-3`) for compact card density
- Kanban column header height: 44px (touch target compliant, contains status label + card count)
- Task detail two-column gap: 24px (`gap-6`) between main content and metadata sidebar
- Checklist item row height: 36px minimum (checkbox + label + actions)
- Checklist item indent for drag handle: 8px left padding before handle
- Comment thread indent: 32px (`pl-8`) left padding for reply comments
- Activity timeline left gutter: 24px (dot + connecting line)
- Activity timeline entry gap: 12px (`gap-3`) between entries
- Mention chip gap: 4px (`gap-1`) between mention chips below textarea
- Dependency row height: 40px (status badge + task title + remove button)
- Subtask row height: 40px (status badge + title + assignee + due date)
- View toggle button group: 0px gap (flush buttons with shared border)

**Source:** Phase 3 UI-SPEC base scale. Phase 5 layout-specific values from CONTEXT.md decisions.

```

| [Due date range: start - end] [x Overdue only]                |
+---------------------------------------------------------------+
| View Toggle: [ Table | Board ]                                 |
+---------------------------------------------------------------+
|                                                                |
| === TABLE VIEW (default) ==============================       |
| DataTable (white card, rounded-lg, shadow-sm)                  |
| Title | Client | Engagement | Status | Priority | Assignee |  |
|       |        |            |(badge) | (badge)  |          |  |
| Due Date | Checklist | Blocked | Actions                  |  |
| ...rows...                                                     |
+---------------------------------------------------------------+
| Pagination: Showing 1-10 of 120    [< 1 2 3 ... 12 >]        |
+---------------------------------------------------------------+
|                                                                |
| === BOARD VIEW (Kanban) ================================       |
| +----------+ +----------+ +----------+ +----------+ +----+    |
| | TO DO    | | IN PROG  | | AWAITING | | REVIEW   | |... |    |
| | (12)     | | (8)      | | CLIENT(3)| | (5)      | |    |    |
| +----------+ +----------+ +----------+ +----------+ +----+    |
| | [Card]   | | [Card]   | | [Card]   | | [Card]   | |    |    |
| | [Card]   | | [Card]   | | [Card]   | | [Card]   | |    |    |
| | [Card]   | |          | |          | |          | |    |    |
| +----------+ +----------+ +----------+ +----------+ +----+    |

```

- **Page header**: Flex row, `items-center justify-between`. Title left (Heading 20px), "Add Task" Button (primary variant, `Plus` icon 16px) right. Navigates to `/tasks/new`.
- **Search input**: max-width 320px on desktop, full-width on mobile. `Search` icon (Lucide, 16px) as left adornment. Placeholder: "Search tasks by title...". Debounced 300ms.
- **Filter bar**: Horizontal flex row, `gap-3`, wraps on mobile (`flex-wrap`). Same FilterBar component pattern as Phase 4. Each filter has a label above (12px, `gray-500`, `font-semibold`).
- **Filter controls**:

| Filter | Component | Behavior |
|--------|-----------|----------|
| Assignee | UserPicker | Single select, shows firm users |
| Client | ClientPicker | Single select, filters engagement dropdown |
| Engagement | Select | Populated from client's engagements when client selected, otherwise all engagements. Shows "All engagements" placeholder |
| Status | Multi-select | Checkboxes in dropdown, multiple statuses selectable. Shows "N selected" when > 1 |
| Priority | Multi-select | Checkboxes in dropdown, same pattern as status |
| Due date range | Two DatePickers (start + end) | Label: "Due date". Side by side with dash separator |
| Overdue only | Checkbox | Inline with filter bar. Label: "Overdue only". Toggles `overdue=true` query param |

- **URL-synced filters**: All filters update URL search params via `goto()` with `replaceState: true`. Filter state is bookmarkable. Pattern: `?search=gst&assignee=uuid&status=TO_DO,IN_PROGRESS&view=table&page=1`
- **View toggle**: Button group positioned between filter bar and content. Two flush buttons: "Table" (`LayoutList` icon) and "Board" (`LayoutGrid` icon, Lucide). Active button: `bg-gray-100 text-gray-900 font-semibold`. Inactive button: `bg-white text-gray-500 hover:text-gray-700`. Both share `border border-gray-200`. Group: `rounded-md overflow-hidden inline-flex`. Stored in URL as `?view=table` or `?view=board`. Default: `table`.
- **View toggle position**: `flex justify-end mt-3 mb-4` between filter bar and content area.

#### Table View

- **DataTable container**: Same as Phase 4 -- `white` bg, `rounded-lg`, `shadow-sm`, `border border-gray-200`
- **DataTable columns**:

| Column | Key | Sortable | Width | Render |
|--------|-----|----------|-------|--------|
| Title | title | yes | auto (min 220px) | Link (`text-blue-600 hover:text-blue-800 hover:underline font-medium`) to `/tasks/[id]`. Parent tasks show expand chevron `ChevronRight` (16px, rotates 90deg on expand) for subtasks |
| Client | client | yes | 140px | Plain text (client displayName) or `--` in `gray-400` for standalone tasks |
| Engagement | engagement | yes | 140px | Plain text (engagement name) or `--` in `gray-400` |
| Status | status | yes | 120px | StatusTransitionDropdown (currentStatus, TASK_STATUS_TRANSITIONS, entityType="task") |
| Priority | priority | yes | 90px | StatusBadge (type="priority") |
| Assignee | assignee | no | 120px | User display name or "Unassigned" in `gray-400 italic` |
| Due Date | dueDate | yes | 100px | Formatted date. Overdue: `text-red-600 font-semibold`. Due within 3 days: `text-amber-600`. Past: normal. Null: `--` in `gray-400` |
| Checklist | checklistProgress | no | 80px | "3/5" text + thin progress bar (4px tall, 48px wide, `rounded-full`, track `gray-200`, fill `green-600`). Hidden if 0/0 |
| Blocked | isBlocked | no | 70px | If blocked: small badge `text-xs font-semibold text-red-600 bg-red-50 border border-red-200 rounded-full px-2 py-0.5` reading "Blocked". If not: empty cell |
| Actions | -- | no | 40px | `MoreHorizontal` icon -> dropdown: "View Details", "Delete Task" |

- **Subtask expansion**: Parent tasks with subtasks show `ChevronRight` icon before title. Click toggles child rows. Child rows indented 24px (`pl-6`), background `gray-50`, slightly smaller row height. Subtask rows show same columns minus the expand chevron. Column values inherit the same rendering.
- **Empty state** (zero tasks): EmptyState with `ClipboardList` icon (Lucide), heading "No tasks yet", body "Create your first task to start tracking work.", actionLabel "Add Task", onAction navigates to `/tasks/new`
- **Filtered empty state**: EmptyState with `SearchX` icon, heading "No tasks match your filters", body "Try adjusting your search or filters.", actionLabel "Clear filters"
- **Loading state**: LoadingSkeleton variant="table" with 10 rows, matching column count

#### Kanban Board View

- **Board container**: Horizontal flex row, `gap-4`, `overflow-x-auto`, `pb-4` for scroll padding. Minimum content width to show all columns -- horizontal scroll on narrow viewports.
- **Column order**: TO_DO | IN_PROGRESS | AWAITING_CLIENT | UNDER_REVIEW | PARTNER_APPROVAL | DONE. CANCELLED is omitted from the board.
- **Column structure**:
  - Container: `bg-gray-100 rounded-lg` minimum width 280px, max width 320px, `flex-shrink-0`
  - Header: `px-3 py-2 flex items-center justify-between`. Status label (Label 14px/600, using status display name), card count in parentheses (`text-gray-400 text-sm font-normal`). Fixed at top (sticky within column if column scrolls).
  - Card list: `px-2 pb-2 space-y-2 overflow-y-auto` max-height calc(100vh - 320px) for vertical scroll within column
  - Column with zero cards: Show subtle text "No tasks" in `text-gray-400 text-xs text-center py-8`

- **Kanban card layout**:

```
+-------------------------------------------+
| [Drag Handle ::] Task title (semibold)    |
|                                            |
| [Priority badge] [Blocked badge]           |
|                                            |
| [Avatar/Name]    [Due: Apr 15] [3/5 bar]  |
+-------------------------------------------+
```

  - Container: `bg-white rounded-md border border-gray-200 p-3 cursor-grab hover:border-gray-300 hover:shadow-sm transition-all duration-150`
  - Drag handle: `GripVertical` icon (Lucide, 14px, `text-gray-300`), visible on hover, left side
  - Title: `text-sm font-semibold text-gray-900 line-clamp-2` (max 2 lines, truncate with ellipsis)
  - Priority badge: StatusBadge (type="priority"), positioned below title with `mt-1.5`
  - Blocked badge: Inline next to priority badge if `is_blocked` is true. Same styling as table view blocked badge.
  - Bottom row: `flex items-center justify-between mt-2 text-xs text-gray-500`
    - Left: Assignee name (truncated, max 100px) or "Unassigned" in `italic`
    - Center: Due date. Same color logic as table (overdue red, due-soon amber)
    - Right: Checklist progress "3/5" with mini progress bar (32px wide, 3px tall). Hidden if no checklist items.

- **Drag-and-drop behavior**:
  - Library: `svelte-dnd-action` (established Svelte DnD library)
  - On drag start: Card elevates with `shadow-lg`, `ring-2 ring-blue-500`, `opacity-90`
  - Drop zone: Column highlights with `bg-blue-50 border-2 border-dashed border-blue-300` when card is dragged over it
  - On drop: Fire `PATCH /api/tasks/:id/status` with the target column's status
  - If transition is invalid (e.g., TO_DO -> DONE): Revert card to original column with smooth animation. Show toast error: "Cannot move to {targetStatus}. Allowed: {allowedStatuses}."
  - If DONE transition blocked by checklist: Revert card. Show toast error: "Cannot mark as done: {N} required checklist items are incomplete."
  - Optimistic update: Card appears in target column immediately. Revert on API error.

**Source:** REQUIREMENTS.md PAGE-04, TASK-07. CONTEXT.md Task List Filters, Task Status Change UX, Kanban decisions.

### Task Create Page

Route: `(app)/tasks/new/+page.svelte`

```

| Page Header                                                    |

+---------------------------------------------------------------+

|                                                                |
| --- ASSIGNMENT ---                                             |
| [Client picker      ] [Engagement picker   ]                  |
| [Assignee picker    ] [Reviewer picker     ]                  |
|                                                                |
| --- SCHEDULING ---                                             |
| [Priority * v]  [Due Date picker] [Internal Due Date picker]  |
|                                                                |
| --- TAGS ---                                                   |
| [Tags (comma-separated input, max 10)       ]                 |
|                                                                |
| --- INITIAL CHECKLIST (optional) ---                           |
| [x] Required  [Item label ________________] [+]               |
| [x] Required  [Item label ________________] [x remove]        |
| ...                                                            |
|                                                                |
| [Cancel]  [Create Task]                                        |
+---------------------------------------------------------------+
```

- **Back link**: `ArrowLeft` icon + "Back to Tasks" text, `text-gray-500 hover:text-gray-700`, 14px. Navigates to `/tasks`
- **Form container**: Same as Phase 4 client form -- `white` bg, `rounded-lg`, `shadow-sm`, `border border-gray-200`, padding 24px (`p-6`)
- **Section headings**: Same as Phase 4 -- 12px, `font-semibold`, `uppercase`, `tracking-wider`, `text-gray-500`, with `border-b border-gray-200 pb-2 mb-4 mt-8` (first section `mt-0`)
- **Form grid**: 2 columns on desktop (`grid grid-cols-2 gap-4`), 1 column on mobile. Title, Description, and Tags span full width (`col-span-2`)
- **Title input**: Required. Max length 300 characters (from shared LIMITS). Placeholder: "Task title"
- **Description textarea**: Optional. Max length 10000 characters. 5 rows. Placeholder: "Describe the task..."
- **Client picker**: ClientPicker component. When selected, filters Engagement dropdown to that client's engagements
- **Engagement picker**: Select dropdown. Disabled with "Select a client first" placeholder until client is chosen. When engagement is selected, auto-fills `clientId` from the engagement's client if not already set
- **Priority**: Select dropdown. Options from TaskPriority enum. Default: MEDIUM. Required.
- **Due Date**: DatePicker. Optional. When set and Internal Due Date is not explicitly provided, internal due date auto-computes (shown as read-only computed value with hint "Auto-calculated: {dueDate} - {buffer} days")
- **Internal Due Date**: DatePicker. Optional. Labeled "Internal deadline". If blank and due date is set, shows computed value as placeholder. If manually set, overrides auto-computation. Validation: must be <= due date.
- **Initial checklist section**: Optional expandable section. Toggle: "Add initial checklist items" text link. Each item: checkbox for `isRequired` (default checked), text input for label, remove button (X icon). "Add item" button or Enter key to add new item. Max 30 items (show "(N/30 max)" counter).
- **Pre-fill from context**: When navigating from engagement detail (`?engagementId=...&clientId=...`), pre-fill those fields as read-only. When from client detail (`?clientId=...`), pre-fill client.
- **Footer**: `flex justify-end gap-3 mt-6 pt-6 border-t border-gray-200`. Cancel (secondary variant, navigates back), "Create Task" (primary variant). Loading state: spinner + "Creating..."

## Interaction Contracts

### Task List Search & Filter

- **Search**: Input with `Search` icon. Debounced 300ms. Sends `search` query param to API. Clears on "Clear filters" action.
- **Filters**: Each filter updates URL query params. Changing any filter resets to page 1. All filters are optional. Filters persist in URL for shareability.
- **Multi-select filters (Status, Priority)**: Dropdown with checkboxes. Selected values joined by comma in URL: `?status=TO_DO,IN_PROGRESS`. Trigger shows "N selected" when multiple values chosen, or the single value name when one is chosen.
- **Client -> Engagement cascade**: Selecting a client filters the engagement dropdown to that client's engagements. Clearing client resets engagement dropdown.
- **Overdue toggle**: Checkbox in the filter bar. Adds `?overdue=true` to URL. Combines with other filters.
- **URL sync**: Full pattern: `?search=gst&assignee=uuid&client=uuid&engagement=uuid&status=TO_DO,IN_PROGRESS&priority=HIGH,URGENT&dueDateStart=2026-04-01&dueDateEnd=2026-04-30&overdue=true&view=board&page=1&limit=25`
- **Filter bar responsive**: On mobile (< 768px), filters stack vertically in a single column. On desktop, horizontal flex row with `flex-wrap` for overflow.

### View Toggle

- **Persistent**: Active view stored in URL (`?view=table` or `?view=board`). Default: table.
- **Shared filter state**: Both views share the same filters and URL params. Switching view preserves all filters.
- **Transition**: Instant swap (no animation between views). Content area re-renders with the selected view.
- **Kanban paging**: Kanban does not paginate -- it loads all tasks matching current filters (up to a reasonable limit, e.g., 200). If more than 200, show a banner: "Showing first 200 tasks. Use filters to narrow results."

### Kanban Drag-and-Drop

- **Library**: `svelte-dnd-action`
- **Drag initiation**: Grab card anywhere (whole card is draggable). Cursor changes to `grab` on hover, `grabbing` during drag.
- **Drag visual**: Card elevates (`shadow-lg`), `ring-2 ring-blue-500`, `opacity-90`. Original position shows a placeholder outline (`border-2 border-dashed border-gray-300 rounded-md`).
- **Drop zone**: Target column highlights with `bg-blue-50 border-2 border-dashed border-blue-300` when card hovers over it.
- **Valid drop**: Status transition API fires. Optimistic: card appears in target column immediately. On success: silent (card stays). On error: revert card to original column with ease animation (300ms), show toast error.
- **Invalid transition**: Detected after API returns 400. Revert + toast error with allowed transitions.
- **DONE checklist gate**: API returns 409. Revert + toast error listing incomplete required items count.
- **Terminal statuses (DONE, CANCELLED)**: Cards in DONE column are not draggable (no grab cursor, no drag handle). CANCELLED tasks not on board.
- **Accessibility**: Keyboard users can use the StatusTransitionDropdown on each card (accessible via tab + enter) as an alternative to drag-and-drop.

### Task Form Validation

- **On blur**: Each field validates individually. Title is required. Priority is required (default MEDIUM).
- **On submit**: All fields validated. If errors, scroll to first error, focus it. Show toast "Please fix the errors below and try again."
- **Internal due date validation**: If both `dueDate` and `internalDueDate` are set, validate `internalDueDate <= dueDate`. Error: "Internal deadline must be on or before the due date."
- **Max lengths**: Title (300), Description (10000), Comment (5000) -- from shared LIMITS. Show character count when nearing limit (last 10%).
- **Submit button**: Disabled while submitting. Shows spinner + "Creating..." text.

### Checklist Interactions

- **Toggle**: Click checkbox fires `PATCH /api/tasks/:taskId/checklist/:id` with `{ isCompleted: !current }`. Optimistic update -- checkbox toggles immediately. Revert on error.
- **Inline edit label**: Click label text enters edit mode (input appears). Enter saves (`PATCH` with `{ label: newLabel }`). Escape cancels. Blur saves.
- **Add item**: Type in bottom input, press Enter. Fires `POST /api/tasks/:taskId/checklist` with `{ label, isRequired: true }`. Input clears. New item appears at bottom.
- **Delete item**: Click X icon. Fires `DELETE /api/tasks/:taskId/checklist/:id`. Item removed from list. No confirmation dialog -- instant delete.
- **Reorder**: Drag items to reorder. On drop, fire `PATCH /api/tasks/:taskId/checklist/:id` with `{ sortOrder: newIndex }`. Optimistic reorder.
- **Max enforcement**: When count reaches 30, add input is disabled. Show "(30/30 max)" hint.

### Comment Interactions

- **Post comment**: Click "Post Comment" or Cmd+Enter. Fires `POST /api/tasks/:taskId/comments` with `{ body, mentions: [...userIds] }`. Comment appears at top of list. Textarea clears. Mention chips clear.
- **Reply**: Click "Reply" on a comment. Opens inline compose box below parent. Posts with `parentCommentId`. Reply appears under parent. Max depth 1 -- replies to replies not allowed.
- **Edit**: Click "Edit" (own comments only). Body replaced with textarea + "Save"/"Cancel" buttons. Save fires `PATCH`. Cancel reverts.
- **Delete**: Click "Delete" (own comments only). Opens ConfirmDialog. On confirm: fires `DELETE`, comment removed from list with fade animation (150ms).
- **Mention**: Type `@` in textarea -> UserPicker popover opens below cursor. Select user -> chip added below textarea, `@name` inserted in textarea text. Max 10 mentions.

### Metadata Sidebar Interactions

- **Inline editing**: Each metadata field is click-to-edit. Click the value area to open the editor (picker, dropdown, or date picker). Save on selection change (pickers auto-save on select). Cancel on Escape or click outside.
- **Optimistic updates**: Sidebar values update immediately. Revert on API error.
- **Status change**: Uses StatusTransitionDropdown. Same validation and confirmation patterns as table/Kanban.
- **Priority change**: Small dropdown with 4 options. Select fires `PATCH /api/tasks/:id` with `{ priority: newPriority }`.
- **Assignee/Reviewer**: UserPicker popover. Select fires `PATCH`. Show "Unassigned" / "None" as clearable option.
- **Due Date / Internal Deadline**: DatePicker popover. Select fires `PATCH`. Show "Clear" option to remove date.
- **Tags**: Click opens TagInput inline. Same pattern as Phase 4 client form tags.

### Dependency Interactions

- **Add dependency**: Click "Add dependency" -> TaskSearchPicker popover opens. Search input filters tasks in the same firm. Excludes current task and tasks that would create a cycle (if detectable client-side). Select fires `POST /api/tasks/:taskId/dependencies`. If cycle detected (400), show toast error.
- **Remove dependency**: Click X on a "Blocked by" row. Fires `DELETE /api/tasks/:taskId/dependencies`. Instant remove, no confirmation.
- **Links**: Task titles in dependency lists are clickable links to their detail pages.

### Subtask Expansion (Table View)

- **Expand trigger**: `ChevronRight` icon on parent task row. Click toggles child rows.
- **Child rows**: Load inline via the parent task's `subtasks` array (included in list response). No separate API call.
- **Visual**: Child rows indented 24px. Background `gray-50`. Chevron rotates 90 degrees when expanded (200ms transition).

### Responsive Behavior (Phase 5 Pages)

| Viewport | Task List (Table) | Task List (Kanban) | Task Detail |
|----------|-------------------|--------------------|-------------|
| >= 1024px (lg) | Full DataTable, 2-row filter bar | All columns visible, horizontal scroll if needed | Two-column (2/3 + 1/3) |
| 768-1023px (md) | Scrollable DataTable, stacked filters | Horizontal scroll, columns 260px min | Single column, sidebar sections below main |
| < 768px (sm) | Horizontal scroll DataTable, stacked filters | Horizontal scroll, cards full column width | Single column, all sections stacked vertically |

- DataTable horizontal scroll: `overflow-x-auto` on the table container. Column min-widths enforced.
- Kanban horizontal scroll: `overflow-x-auto` on the board container. Column `flex-shrink-0`.
- Task detail responsive switch: `grid grid-cols-1 lg:grid-cols-3`. Below 1024px, sidebar stacks below main content in this order: metadata fields, dependencies, activity.
