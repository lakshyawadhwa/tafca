Build the SvelteKit auth infrastructure and auth pages — login, register, auth guard hook, token management, and the design system foundation (font, theme tokens, types).

Purpose: This is the entry point for the entire frontend. Without auth working, no protected page can be reached. This plan establishes the dual-token flow (access token in memory, refresh via HTTP-only cookie), the SvelteKit hooks.server.ts auth guard, and the two public pages users interact with first.

Output: Working login and register pages that authenticate against the Phase 2 NestJS backend, redirect to / on success, and redirect unauthenticated users away from protected routes.
</objective>

<interfaces>
<!-- Backend auth endpoints (from Phase 2 auth.controller.ts) -->
POST /api/auth/login
  Request: { email: string, password: string }
  Response: { accessToken: string, user: { id, email, fullName, role, firmId, firmName, avatarUrl } }
  Sets HTTP-only cookie: refresh_token (path: /api/auth, 7 days)

POST /api/auth/register
  Request: { email: string, password: string, fullName: string, firmName: string }
  Response: { accessToken: string, user: {...}, firm: { id, name, slug } }
  Sets HTTP-only cookie: refresh_token (path: /api/auth, 7 days)

POST /api/auth/refresh
  Request: {} (refresh_token cookie sent automatically)
  Response: { accessToken: string }

POST /api/auth/logout
  Headers: Authorization: Bearer {accessToken}
  Response: 204

GET /api/auth/me
  Headers: Authorization: Bearer {accessToken}
  Response: { id, email, fullName, role, firmId, firmName, avatarUrl, isActive, phone, ... }

<!-- JWT payload shape -->
{ sub: string, firmId: string, role: UserRole, email: string, sessionId: string }

<!-- Shared package enums (from @ca-practice-os/shared) -->
UserRole: PARTNER | MANAGER | JUNIOR_CA | ARTICLE | ADMIN

    **1. app.html** — Add Inter font CDN link to head (weights 400, 600; subsets latin, latin-ext). Use preconnect to fonts.googleapis.com and fonts.gstatic.com per UI-SPEC Typography section.

    **2. app.css** — Add @theme directive after @import 'tailwindcss'. Only token needed: `--font-sans: 'Inter', ui-sans-serif, system-ui, -apple-system, sans-serif;`. No color overrides — TailwindCSS v4 default palette already has all UI-SPEC colors.

    **3. app.d.ts** — Define App.Locals (accessToken: string, user with id/email/fullName/role/firmId/firmName/avatarUrl), App.PageData (user, accessToken — both optional), and App.Error (message, statusCode). Import UserRole from @ca-practice-os/shared.

    **4. vite.config.ts** — Add server.proxy to proxy `/api` requests to `http://localhost:3000` with changeOrigin: true. This makes the backend accessible from the dev server without CORS issues.

    **5. hooks.server.ts** — Implement auth guard using the handle hook:
    - Define PUBLIC_PATHS: ['/login', '/register']
    - For public paths, resolve immediately
    - For protected paths, check `access_token` cookie
    - If no cookie, try refresh by POSTing to /api/auth/refresh via event.fetch (refresh_token cookie auto-sent since path is /api/auth)
    - On successful refresh, set new access_token cookie (httpOnly, sameSite: lax, path: /, maxAge: 14*60 seconds — slightly less than 15min JWT expiry)
    - Also call GET /api/auth/me to populate event.locals.user
    - If cookie exists, set event.locals.accessToken from cookie, call /api/auth/me to populate event.locals.user
    - If all fails, redirect(303, '/login')
    - For already-authenticated users hitting /login or /register, redirect to /
    - Use sequence() from @sveltejs/kit/hooks for composability
    - CRITICAL: re-throw redirect errors (check for status property) — don't catch them in the try/catch

    **6. auth.svelte.ts** — Svelte 5 rune-based auth store in .svelte.ts file:
    - AuthUser interface: { id, email, fullName, role: UserRole, firmId, firmName, avatarUrl: string | null }
    - Use object pattern for cross-module reactivity: `const authState = $state<{ accessToken: string | null, user: AuthUser | null }>({...})`
    - Export functions: getAccessToken(), setAuth(token, user), clearAuth(), getUser()
    - NEVER use localStorage for tokens

    **7. toast.svelte.ts** — Toast notification store:
    - ToastVariant type: 'success' | 'error' | 'info'
    - Toast interface: { id: string, message: string, variant: ToastVariant }
    - MAX_VISIBLE = 3, auto-dismiss: error 8s, success/info 4s
    - Export: addToast(message, variant), removeToast(id), getToasts()
    - Use crypto.randomUUID() for toast IDs, setTimeout for auto-dismiss

    **8. api.ts** — Authenticated fetch wrapper:
    - Export async function `api<T>(path, options?)` that prepends API_BASE (empty string — Vite proxy handles routing)
    - Attach Authorization: Bearer header from getAccessToken()
    - Set Content-Type: application/json
    - On 401: attempt refresh (POST /api/auth/refresh, credentials: include), retry original request once with new token. Use a shared refreshPromise to deduplicate concurrent refresh calls.
    - On refresh failure: clearAuth(), goto('/login'), throw Error
    - On non-ok: parse JSON error body and throw it
    - CRITICAL: API_BASE should be '/api' since the Vite proxy is configured to forward /api to backend, and the NestJS backend has setGlobalPrefix('api')

    **9. Button.svelte** — Per UI-SPEC Button Variants section:
    - Props (via $props()): variant ('primary'|'secondary'|'ghost'|'danger', default 'primary'), size ('sm'|'md'|'lg', default 'md'), loading (boolean), disabled (boolean), type ('button'|'submit', default 'button'), onclick handler, children Snippet
    - Size classes: sm=h-9 px-3, md=h-11 px-4, lg=h-12 px-6
    - Variant classes per UI-SPEC table (primary=blue-600/white, secondary=white/gray-700 bordered, ghost=transparent/gray-600, danger=red-600/white)
    - All: rounded-md, focus ring 2px blue-600 offset 2px, disabled:opacity-50
    - Loading: show spinner SVG, disable button

    **10. Input.svelte** — Form input primitive:
    - Props: type (default 'text'), value (bindable), placeholder, error (string|null), disabled, id, name
    - 40px height, 16px horizontal padding, rounded-md
    - Normal border: gray-200, hover: gray-300, focus: blue-600 ring
    - Error: red-500 border, red-600 focus ring
    - Disabled: gray-100 bg, gray-400 text

    **11. ToastContainer.svelte** — Renders toast list:
    - Fixed position top-right, 24px from edges (per UI-SPEC)
    - Renders getToasts() with variant-based styling (success=green, error=red, info=blue)
    - Each toast: white bg, shadow-lg, rounded-md, 360px wide
    - X button to dismiss via removeToast()
    - Use Lucide icons for variant indicators (CheckCircle2, XCircle, Info)

    **12. Root +layout.svelte** — Update existing:
    - Keep `import '../app.css'` and children pattern
    - Add ToastContainer component (renders on all pages)
    - If page data has accessToken + user, call setAuth() to hydrate client-side auth store via $effect
    - Import type from $props(), use Snippet typing for children

    **13. Root +layout.server.ts** — Create:
    - Load function returns { user: locals.user ?? null, accessToken: locals.accessToken ?? null }
    - This passes server-side auth state to all pages via page data
