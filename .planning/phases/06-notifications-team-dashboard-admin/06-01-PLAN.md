**Then, create the Team module:**

3. **DTOs:**
   - `workload-response.dto.ts`: `WorkloadUserDto` with userId, fullName, role, avatarUrl (nullable), openTaskCount, overdueTaskCount, dueThisWeekCount, loadStatus (WorkloadStatus string). `WorkloadResponseDto`: `{ data: WorkloadUserDto[], firmAverage: number }`.
   - `create-leave.dto.ts`: `CreateLeaveDto` with `leaveType` (IsEnum(LeaveType)), `startDate` (IsDateString), `endDate` (IsDateString), `isHalfDay` (optional, IsBoolean, default false), `reason` (optional, IsString, MaxLength(500)).    - `list-leave-query.dto.ts`: `ListLeaveQueryDto` with `status` (optional, IsEnum(LeaveStatus)), `userId` (optional, IsUUID), `page` (optional, default 1), `limit` (optional, default 20).

   - `approval-queue-response.dto.ts`: `ApprovalQueueItemDto` with id, title, clientName (nullable), dueDate, priority, assigneeName. `PaginatedApprovalQueueResponseDto`.

4. **`team.service.ts`** -- Extends FirmScopedService. Two main methods:

   **`getWorkload()`** (per TEAM-01):
   - Fetch all active users in firm: `this.prisma.user.findMany({ where: { isActive: true }, select: { id, fullName, role, avatarUrl } })`.
   - Use `this.unscopedPrisma.task.groupBy()` for aggregate counts. Run 3 parallel groupBy queries via `Promise.all()`:
     - Open tasks: `groupBy({ by: ['assigneeId'], where: { firmId, status: { notIn: [DONE, CANCELLED] }, deletedAt: null }, _count: { id: true } })`
     - Overdue tasks: same + `dueDate: { lt: startOfToday }`
     - Due this week: same + `dueDate: { gte: startOfToday, lte: startOfToday + 7 days }`
   - IMPORTANT: Use `this.unscopedPrisma` with explicit `firmId` in WHERE because groupBy with scoped client may have issues. Always include `deletedAt: null`.
   - Build a map of userId -> counts. Compute `firmAverage = totalOpen / activeUserCount` (0 if no users).
   - Assign load status per user: `< 0.5x avg` = UNDERUTILISED, `0.5x - 1.5x` = BALANCED, `> 1.5x` = OVERLOADED. If firmAverage === 0, everyone is BALANCED.
   - Return `{ data: WorkloadUserDto[], firmAverage }`.

   **`getApprovalQueue(userId, userRole, query)`** (per TEAM-04):
   - Only meaningful for PARTNER/MANAGER roles. For others, return empty list.
   - Query tasks WHERE `status = TaskStatus.PARTNER_APPROVAL` AND `(reviewerId = userId OR engagement.assignedPartnerId = userId)`.
   - Use `this.prisma.task.findMany()` with OR condition. Include client name via `select: { client: { select: { displayName: true } } }` and assignee via `select: { assignee: { select: { fullName: true } } }`.
   - Order by `dueDate ASC, priority DESC`. Paginate.
   - Return paginated response.

5. **`leave.service.ts`** -- Extends FirmScopedService:

   **`createLeave(dto: CreateLeaveDto)`** (per TEAM-02):
   - Validate no overlapping leaves: query existing PENDING or APPROVED leaves WHERE `userId = this.getUserId()` AND `startDate <= dto.endDate` AND `endDate >= dto.startDate`. If found, throw ConflictException("Leave request overlaps with an existing leave").
   - Create via `this.prisma.leaveRecord.create()` with `userId: this.getUserId()`, `createdBy: this.getUserId()`, `updatedBy: this.getUserId()`, `status: LeaveStatus.PENDING`.
   - Return created record as DTO.

   **`listLeave(query: ListLeaveQueryDto)`** (per TEAM-02):
   - For PARTNER/MANAGER: return all firm leave requests. For others: filter `userId = this.getUserId()`.
   - The role info comes from the controller injecting it. Apply optional status and userId filters from query.
   - Batch-fetch user names for `userId` and `approvedBy` fields (same pattern as ActionLogService -- collect unique IDs, single findMany, build userMap).
   - Order by `startDate DESC`. Paginate with standard meta.

   **`approveLeave(leaveId: string)`** (per TEAM-03):
   - Find leave WHERE id AND status = PENDING. Not found or not PENDING -> NotFoundException/BadRequestException.
   - Update `status = APPROVED`, `approvedBy = this.getUserId()`, `approvedAt = new Date()`, `updatedBy = this.getUserId()`.
   - Fire-and-forget: emit ASSIGNEE_ON_LEAVE notification for tasks assigned to the leave user with dueDate within the leave range (query tasks, create notifications via unscopedPrisma -- same fire-and-forget pattern as TaskNotificationHelper).
   - Return updated DTO.

   **`rejectLeave(leaveId: string, reason?: string)`** (per TEAM-03):
   - Find leave WHERE id AND status = PENDING. Not found or not PENDING -> error.
   - Update `status = REJECTED`, `approvedBy = this.getUserId()`, `approvedAt = new Date()`, `updatedBy = this.getUserId()`.
   - Return updated DTO.

   **`cancelLeave(leaveId: string)`**:
   - Find leave WHERE id AND `userId = this.getUserId()`. Must be PENDING, or APPROVED with startDate in the future.
   - Update `status = CANCELLED`, `updatedBy = this.getUserId()`.
   - Return updated DTO.
