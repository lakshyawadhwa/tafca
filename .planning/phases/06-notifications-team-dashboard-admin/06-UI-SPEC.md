# Phase 6 -- UI Design Contract

> Visual and interaction contract for Notifications, Team, Dashboard & Admin pages. Generated by gsd-ui-researcher, verified by gsd-ui-checker. **Extends** the Phase 3-5 design system -- all tokens (spacing, typography, color, component APIs) carry forward unchanged.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (SvelteKit -- shadcn not applicable) |
| Preset | not applicable |
| Component library | Custom Svelte 5 components with TailwindCSS (Phase 3 + 4 + 5 library) |
| Icon library | Lucide (lucide-svelte) |
| Font | Inter via CDN (Google Fonts), weights 400, 600 |

**Inherited from:** Phase 3 UI-SPEC (03-UI-SPEC.md), extended by Phase 4 (04-UI-SPEC.md) and Phase 5 (05-UI-SPEC.md). No changes to the design system foundation.

## Spacing Scale

Inherited from Phase 3. No changes to base scale.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, badge padding-x |
| sm | 8px | Compact element spacing, input padding-y, table cell padding |
| md | 16px | Default element spacing, card padding, input padding-x |
| lg | 24px | Section padding, sidebar item padding-x, modal padding |
| xl | 32px | Layout gaps, sidebar padding-y, form group spacing |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Phase 6 exceptions:
- Dashboard stat card padding: 20px (`p-5`) -- slightly larger than md for card breathing room
- Dashboard stat card gap: 16px (`gap-4`) between stat cards in the grid
- Dashboard section gap: 24px (`gap-6`) between major dashboard sections (summary row, task/approval columns, notifications)
- Notification dropdown width: 360px fixed width
- Notification dropdown max-height: 400px with internal scroll
- Notification item padding: 12px horizontal, 10px vertical (`px-3 py-2.5`) for compact list density
- Notification unread dot size: 8px (`h-2 w-2`)
- Notification bell badge position: offset `right-1 top-1` from bell button
- Admin sidebar section divider: 16px (`mt-4 mb-2`) vertical spacing above the "ADMIN" label
- Countdown badge padding: 4px horizontal, 2px vertical (`px-1 py-0.5`) for compact countdown display
- Settings tabs content top margin: 24px (`mt-6`) below tab bar
- Leave form half-day toggle gap: 8px (`gap-2`) between checkbox and label

**Source:** Phase 3 UI-SPEC base scale. Phase 6 layout-specific values from CONTEXT.md decisions and Claude's Discretion.

## Typography

Inherited from Phase 3. No changes.

| Role | Size | Weight | Line Height | Tailwind Class |
|------|------|--------|-------------|----------------|
| Body | 14px | 400 (regular) | 1.5 (21px) | `text-sm font-normal leading-relaxed` |
| Label | 14px | 600 (semibold) | 1.4 (19.6px) | `text-sm font-semibold leading-snug` |
| Heading | 20px | 600 (semibold) | 1.2 (24px) | `text-xl font-semibold leading-tight` |
| Display | 28px | 600 (semibold) | 1.2 (33.6px) | `text-2xl font-semibold leading-tight` |

Phase 6 role assignments within the existing type scale:
- Dashboard greeting: Heading (20px/600) -- "Welcome back, {firstName}"
- Dashboard stat card count: Display (28px/600) in relevant semantic color (red for overdue, amber for due today, blue for due this week, purple for in review)
- Dashboard stat card label: Body (14px/400) in `text-gray-500`
- Dashboard section title: Label (14px/600) -- "My Tasks", "Approval Queue", "Recent Notifications"
- Dashboard "View all" link: 12px/400 (`text-xs`) in `text-blue-600 hover:text-blue-800`
- Notification dropdown header: Label (14px/600) -- "Notifications"
- Notification dropdown "Mark all read": 12px/600 (`text-xs font-semibold`) in `text-blue-600 hover:text-blue-800`
- Notification item title: Body (14px/400) in `text-gray-900` (unread) or `text-gray-600` (read)
- Notification item body: 12px/400 (`text-xs`) in `text-gray-500`, truncated to 1 line (`line-clamp-1`)
- Notification item timestamp: 12px/400 (`text-xs`) in `text-gray-400`
- Notification empty text: Body (14px/400) in `text-gray-400`
- Team workload page title: Heading (20px/600) -- "Team Workload"
- Workload stat (numeric columns): Body (14px/400) in `text-gray-900`, overdue count in `text-red-600 font-semibold` when > 0
- Leave page tab labels: Label (14px/600) for active tab, Body (14px/400) for inactive
- Leave form section labels: Label (14px/600)
- Leave date range text: Body (14px/400)
- Leave reason text: Body (14px/400) in `text-gray-600`
- Settings page title: Heading (20px/600) -- "Settings"
- Settings section heading: Label (14px/600) -- "Task Defaults", "Workflow"
- Settings help text: 12px/400 (`text-xs`) in `text-gray-500`
- User table role cell: Body (14px/400) via StatusBadge
- Audit log timestamp: 12px/400 (`text-xs font-mono`) for monospace timestamp rendering
- Audit log metadata preview: 12px/400 (`text-xs font-mono`) in `text-gray-500`
- Recently deleted countdown badge: 12px/600 (`text-xs font-semibold`)
- Admin sidebar section label: 11px/600 (`text-[11px] font-semibold uppercase tracking-widest`) in `text-gray-400`

**Source:** Phase 3 typography scale. Phase 6 assigns roles within the existing scale.

+---------------------------------------------------------------+

**Greeting line:**
- Left: "Welcome back, {firstName}" in Heading (20px/600, `text-gray-900`)
- Right: Today's date formatted as "Friday, 4 April 2026" in Body (14px/400, `text-gray-500`)
- Container: `flex items-center justify-between mb-6`

**Section 1: Task Summary Cards**
- Container: `grid grid-cols-2 lg:grid-cols-4 gap-4`
- Each card: `bg-white rounded-lg border border-gray-200 p-5 cursor-pointer hover:shadow-sm transition-shadow`
- Left accent border: 3px solid in semantic color (`border-l-[3px]`). Overdue: `border-l-red-500`. Due Today: `border-l-amber-500`. Due This Week: `border-l-blue-500`. In Review: `border-l-purple-500`
- Count: Display (28px/600) in semantic color
- Label: Body (14px/400) in `text-gray-500`, below count with `mt-1`
- Click: navigates to filtered `/tasks` page (per CONTEXT.md URL mappings)
- "In Review" card: Only rendered for PARTNER and MANAGER roles. When role is JUNIOR_CA, ARTICLE, or ADMIN, grid shows 3 cards spanning `grid-cols-3`

**Section 2: My Tasks + Approval Queue**
- Container: `grid grid-cols-1 lg:grid-cols-5 gap-6 mt-6`
- My Tasks column: `col-span-3` on desktop, full width on mobile
- Approval Queue column: `col-span-2` on desktop, full width on mobile. Hidden entirely for non-PARTNER/MANAGER roles (My Tasks takes full width `col-span-5`)

**My Tasks card:**
- Container: `bg-white rounded-lg border border-gray-200 p-6`

  - StatusBadge (type="task", compact)
  - Title: Body (14px/400), `text-gray-900`, truncated 1 line (`truncate`), clickable (navigates to `/tasks/[id]`)
  - Priority dot: 8px colored circle matching priority color (not full badge, just a dot for density)
  - Due date: 12px, right-aligned, with overdue/due-soon color logic (red if past, amber if within 3 days)
- Empty state: "No tasks assigned to you" in Body (14px/400) `text-gray-400`, centered, `py-8`
- Max 10 items. If more, count shown in "View all" link: "View all (24)"

**Approval Queue card:**

- Header: "Approval Queue" label. "View all" link.
- Each row: `flex items-center gap-3 py-2.5 border-b border-gray-100 last:border-0`
  - Task title: Body (14px/400), `text-gray-900`, clickable, truncated
  - Client name: 12px, `text-gray-500`
  - Due date: 12px, with color logic
  - Priority: StatusBadge (type="priority", compact)
- Empty state: "No tasks pending approval" in `text-gray-400`, centered, `py-8`

**Section 3: Recent Notifications**
- Container: `bg-white rounded-lg border border-gray-200 p-6 mt-6`
- Header: `flex items-center justify-between mb-4`. "Recent Notifications" in Label (14px/600). "View all" link.
- Each notification row: Same layout as notification dropdown items (see Notification Dropdown section below)
- Max 5 items. Empty state: "All caught up -- no recent notifications." in `text-gray-400`, centered, `py-8`

### Notification Dropdown

Component: `$lib/components/layout/NotificationBell.svelte` (replaces bell button in Topbar.svelte)

```
+--- Bell Icon Button ---+
| [Bell] [count badge]   |
+------------------------+
         |
         v (dropdown below, right-aligned)
+---------------------------------------------+
| Notifications              [Mark all read]  |
+---------------------------------------------+
| [icon] Title text               2h ago  [.] |
|        Body preview truncated               |
+---------------------------------------------+
| [icon] Title text               5h ago      |
|        Body preview truncated               |
+---------------------------------------------+
| ... (max 20 items, scrollable) ...          |
+---------------------------------------------+
| View all notifications                      |
+---------------------------------------------+
```

**Bell button (in Topbar):**
- Replaces the existing placeholder bell in Topbar.svelte
- Button: `relative rounded-md p-2 text-gray-500 hover:bg-gray-100 hover:text-gray-700` (unchanged from existing)
- Badge: Absolutely positioned, `top-1 right-1`. When count > 0: red circle with white count text. Size: `min-w-[18px] h-[18px] rounded-full bg-red-500 text-white text-[10px] font-bold flex items-center justify-center`. When count > 99: show "99+". When count is 0: badge hidden.
- Click: toggles dropdown open/closed

**Dropdown panel:**
- Position: Absolutely positioned below the bell button, right-aligned. `absolute right-0 top-full mt-2`
- Container: `w-[360px] max-h-[400px] bg-white rounded-lg border border-gray-200 shadow-lg overflow-hidden`
- Z-index: `z-50` (above all page content)
- Close: click outside, Escape key

**Dropdown header:**
- Container: `flex items-center justify-between px-4 py-3 border-b border-gray-200`
- "Notifications" in Label (14px/600)
- "Mark all read" text button: 12px/600, `text-blue-600 hover:text-blue-800 cursor-pointer`. Hidden when no unread notifications.

**Notification item:**
- Container: `flex items-start gap-3 px-4 py-2.5 cursor-pointer hover:bg-gray-100 border-b border-gray-100 last:border-0`
- Unread items: `bg-gray-50` background (read items: `bg-white`)
- Left: Lucide icon (16px, `text-gray-500`, `mt-0.5`) based on notification type:
  - `TASK_ASSIGNED` -> `UserPlus`
  - `TASK_REVIEW_REQUESTED` / `TASK_APPROVAL_REQUESTED` -> `ClipboardCheck`
  - `TASK_SENT_BACK` -> `RotateCcw`
  - `TASK_DEPENDENCY_UNBLOCKED` -> `Unlock`
  - `COMMENT_MENTION` -> `AtSign`
  - Default -> `Bell`
- Center (flex-1):
  - Title: Body (14px/400), `text-gray-900` (unread) or `text-gray-600` (read), `line-clamp-1`
  - Body: 12px, `text-gray-500`, `line-clamp-1 mt-0.5`
- Right:
  - Timestamp: 12px, `text-gray-400`, `whitespace-nowrap`
  - Unread dot: 8px circle, `bg-blue-600 rounded-full`, `mt-1.5` below timestamp. Hidden for read items.
- Click: marks notification as read (if unread), navigates to entity route:
  - `entityType = 'Task'` -> `/tasks/${entityId}`
  - `entityType = 'Client'` -> `/clients/${entityId}`
  - `entityType = 'Engagement'` -> `/engagements/${entityId}`
  - Fallback: close dropdown, no navigation

**Dropdown scrollable area:**
- Container: `overflow-y-auto max-h-[320px]` (header + footer take ~80px from the 400px max)
- Max 20 notifications loaded

**Dropdown footer:**
- Container: `px-4 py-3 border-t border-gray-200 text-center`
- "View all notifications" link: 12px, `text-blue-600 hover:text-blue-800` (stretch goal -- navigates to `/notifications` if built, otherwise hidden)

**Polling:**
- On mount: fetch `GET /api/notifications/unread-count` to set badge
- Interval: every 60 seconds, re-fetch unread count
- On dropdown open: fetch `GET /api/notifications?limit=20` to populate list
- After mark-read or mark-all-read: re-fetch unread count and refresh list

**Source:** CONTEXT.md Notification Bell UX decisions. NOTIF-01 through NOTIF-04.

## Interaction Contracts

### Notification Bell Behavior

- **Polling**: Fetch unread count on mount, then every 60 seconds via `setInterval`. Clear interval on component destroy.
- **Dropdown open**: Fetch notification list (20 items) on open. Show skeleton while loading.
- **Mark single read**: On notification click. Optimistic update (immediately mark as read in local state). Fire `PATCH /api/notifications/:id/read`. On error: revert local state, show error toast.
- **Mark all read**: Fire `PATCH /api/notifications/read-all`. Optimistic update. On success: update badge count to 0.
- **Navigate on click**: After marking as read, navigate via `goto()` to entity route.
- **Click outside close**: Use a Svelte action or event listener on `document` to close dropdown when clicking outside.
- **Escape close**: Listen for Escape key while dropdown is open.
- **Animation**: Dropdown slides down from top with `transform translateY(-8px) -> translateY(0)` and `opacity 0 -> 1` over 150ms ease-out.

### Dashboard Data Loading

- **SSR**: Dashboard data loaded via `+page.server.ts` calling `GET /api/dashboard`.
- **Loading state**: Full-page LoadingSkeleton with card-shaped skeletons for stat row, and table-shaped skeletons for task/approval sections.
- **Error state**: If API fails, show a centered error message with "Retry" button that calls `invalidateAll()`.
- **Stat card click**: Uses `goto()` for client-side navigation to filtered task views.
- **Refresh**: No auto-refresh on dashboard. User can refresh the browser. Notification badge updates independently via polling.

### Leave Approval Flow

- **Approve**: Single click on "Approve" button. No confirmation dialog (approving is a positive action, low risk). Fires `PATCH /api/team/leave/:id/approve`. On success: row updates to show APPROVED badge, toast shown.
- **Reject**: Click "Reject" button opens LeaveRejectModal with optional reason. On confirm: fires `PATCH /api/team/leave/:id/reject` with optional reason body. On success: row updates to show REJECTED badge, toast shown.
- **Optimistic**: No optimistic updates for approval actions (important state changes should wait for server confirmation).
- **After action**: Button area on the row transitions to a StatusBadge (APPROVED or REJECTED) with a subtle fade transition (200ms).

### Settings Save Behavior

- **Explicit save**: No auto-save. User clicks "Save Settings" to persist. Button disabled until form state differs from server state (dirty check).
- **Dirty check**: Compare current form values against initial loaded values. Enable save button only when different.
- **On save**: Fire `PATCH /api/firms/settings` with changed fields. Show spinner on button. On success: toast + update initial values to match saved values (reset dirty state).
- **Navigation guard**: If user tries to navigate away with unsaved changes, no blocking prompt in V1 (keep it simple).

### User Deactivation Flow

- **Click deactivate**: Opens ConfirmDialog with danger variant
- **On confirm**: Fire `PATCH /api/users/:id/deactivate`. On success: check response `openTasksCount`.
  - If 0: toast "{userName} deactivated."
  - If > 0: toast "{userName} deactivated. {count} open tasks need reassignment."
- **Table update**: Row updates to show Inactive status badge. Deactivate button disappears.

### Audit Log Expandable Rows

- **Toggle**: Click `ChevronRight` icon to expand/collapse metadata section
- **Animation**: Height transition 200ms ease-in-out. `ChevronRight` rotates 90 degrees when expanded.
- **Multiple rows**: Multiple rows can be expanded simultaneously (no accordion behavior).
- **Server-side pagination**: Filters update URL params, trigger `load` function re-fetch.

### Recently Deleted Restore

- **Click restore**: Opens ConfirmDialog (default variant, not danger)
- **On confirm**: Fire `POST /api/recently-deleted/:entityType/:entityId/restore`. On success: row fades out (200ms), table refreshes, toast shown.
- **On error**: Toast with error message. Common error: "This record may have been permanently deleted."
