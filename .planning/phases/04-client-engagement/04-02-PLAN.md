<objective>
Build the Engagement and EngagementType backend modules -- engagement CRUD with lifecycle status transitions, auto-name generation, partner/manager inheritance from client, template task instantiation (two-pass algorithm), and an EngagementType read-only API for dropdowns and template preview.

Purpose: Engagements link clients to the work being done. This is the first domain workflow -- creating an engagement can spawn a full task chain from a template, which is the core productivity feature. The EngagementType API provides dropdown data and template preview for the frontend create modal.

Output: Working Engagement API at `/api/engagements` + `/api/engagements/:id/status`, and EngagementType API at `/api/engagement-types` + `/api/engagement-types/:id/template`.

**Engagement Service (apps/api/src/engagement/engagement.service.ts):**
- extends FirmScopedService
- Constructor: inject PrismaService (via super) and EngagementTypeService

`createEngagement(dto)`:
1. Verify client exists in firm: `this.prisma.client.findUnique({ where: { id: dto.clientId } })`. Throw NotFoundException if not found.
2. Verify engagement type exists: Use `unscopedPrisma` (same reason as EngagementType service -- platform types have firmId null). Throw NotFoundException if not found.
3. **Auto-generate name (ENG-02)**: If `dto.name` is not provided, generate as `"[engagementType.name] - [client.displayName] - [dto.periodLabel]"`. If periodLabel is null, omit the last segment. Truncate to 200 chars.
4. **Inherit partner/manager (ENG-03)**: If `dto.assignedPartnerId` is null/undefined, copy from `client.assignedPartnerId`. Same for `assignedManagerId`. This is a one-time copy.
5. Create the engagement record with all fields, `createdBy` and `updatedBy` = `this.getUserId()`.
6. **Template instantiation (ENG-04)**: If `dto.autoCreateTasks` is true:
   a. Look up `engagementType.defaultTaskTemplateId`
   b. If template exists, call `instantiateTasksFromTemplate()` (see below)
   c. Return engagement + task count in response
7. Return engagement response.

`instantiateTasksFromTemplate(engagement, client, templateId)`:
- Fetch template with items ordered by displayOrder
- If not active or no items, return 0
- Build roleMap: `{ PARTNER: client.assignedPartnerId, MANAGER: client.assignedManagerId, JUNIOR_CA: client.assignedJuniorId, ARTICLE: client.assignedArticleId }`
- **Two-pass algorithm (critical per RESEARCH.md Pitfall 2):**
  - Pass 1: Create all Task records using `this.unscopedPrisma.task.create()` (need unscopedPrisma because we're setting firmId explicitly). Build a `Map<displayOrder, taskId>`. Set `dueDate = engagement.periodEnd + dueOffsetDays` (use date-fns addDays or manual Date arithmetic). Set status = 'TO_DO', priority = 'MEDIUM'.
  - Pass 2: For each item with non-empty `dependsOnOrder`, create TaskDependency records using the map to resolve order -> taskId.
  - Wrap BOTH passes in a single `this.unscopedPrisma.$transaction()` for atomicity.
- Return the count of tasks created.

`listEngagements(query)`: Same pagination pattern as client list. Include client name, type name, and task progress. Task progress: count tasks where engagementId matches, group by done/total using `_count`. Per ENG-05.

`getEngagement(id)`: Include client, type, task counts.

`updateEngagement(id, dto)`: Standard PATCH. Do not allow clientId/typeId changes.

`changeEngagementStatus(id, dto)`:
1. Fetch current engagement
2. Validate transition: Check `ENGAGEMENT_STATUS_TRANSITIONS[current.status]` includes `dto.status`. If not, throw BadRequestException with `allowed_transitions` array.
3. **COMPLETED check (ENG-07)**: If target is COMPLETED, count tasks where `engagementId = id AND status NOT IN (DONE, CANCELLED)`. If count > 0, throw ConflictException('Cannot complete this engagement. N open tasks must be completed or cancelled first.').
4. **CANCELLED cascade (ENG-08)**: If target is CANCELLED, run `this.prisma.task.updateMany({ where: { engagementId: id, status: { in: ['TO_DO', 'IN_PROGRESS'] } }, data: { status: 'CANCELLED', cancelledAt: new Date(), updatedBy: this.getUserId() } })`. Count affected rows for response.
5. Set `completedAt` timestamp if transitioning to COMPLETED.
6. Update engagement status.
