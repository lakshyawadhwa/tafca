# Phase 4 — UI Design Contract

> Visual and interaction contract for Client & Engagement Management pages. Generated by gsd-ui-researcher, verified by gsd-ui-checker. **Extends** the Phase 3 design system — all tokens (spacing, typography, color, component APIs) carry forward unchanged.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (SvelteKit -- shadcn not applicable) |
| Preset | not applicable |
| Component library | Custom Svelte 5 components with TailwindCSS (Phase 3 library) |
| Icon library | Lucide (lucide-svelte) |
| Font | Inter via CDN (Google Fonts), weights 400, 600 |

**Inherited from:** Phase 3 UI-SPEC (03-UI-SPEC.md). No changes to the design system foundation.

## Spacing Scale

Inherited from Phase 3. No changes.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, badge padding-x |
| sm | 8px | Compact element spacing, input padding-y, table cell padding |
| md | 16px | Default element spacing, card padding, input padding-x |
| lg | 24px | Section padding, sidebar item padding-x, modal padding |
| xl | 32px | Layout gaps, sidebar padding-y, form group spacing |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Phase 4 exceptions:
- Filter bar horizontal gap: 12px (`gap-3`) between filter controls for tighter horizontal density
- Tab underline thickness: 2px (border-bottom for active tab indicator)
- Client detail two-column gap: 24px (`gap-6`) between left info column and right GST/team column
- Form section divider spacing: 32px (`mt-8`) between form sections (Basic Info, Statutory IDs, Contact, Team)

**Source:** Phase 3 UI-SPEC, extended with Phase 4 layout-specific values.

- **Page header**: Flex row, `items-center justify-between`. Title left (Heading 20px), "Add Client" Button (primary variant, `Plus` icon from Lucide, 16px) right

- **Filter bar**: Horizontal flex row below search, `gap-3`, wraps on mobile (`flex-wrap`). Each filter is a Select/Dropdown component with label above (12px, `gray-500`, `font-semibold`).
- **DataTable container**: `white` bg, `rounded-lg`, `shadow-sm`, `border border-gray-200`, `mt-4` below filter bar
- **DataTable columns**:

| Column | Key | Sortable | Width | Render |
|--------|-----|----------|-------|--------|

### Engagement Status Transition UX

Status changes happen via a dropdown on engagement rows and client detail engagements tab.

- **Status dropdown trigger**: Click on the StatusBadge itself or a `ChevronDown` icon next to it. Dropdown shows only valid target statuses from `ENGAGEMENT_STATUS_TRANSITIONS` map.
- **Dropdown items**: Each valid target status rendered as a StatusBadge with the target status value. Hover: `bg-gray-100`.
- **COMPLETED transition**: Opens ConfirmDialog before executing.
  - If allowed: title "Complete this engagement?", message "This is permanent. The engagement cannot be reopened.", confirmLabel "Complete", variant "default"
  - If blocked by open tasks: title "Cannot complete engagement", message "This engagement has {N} open tasks that must be completed or cancelled first.", confirmLabel disabled or hidden, show "View Open Tasks" link
- **CANCELLED transition**: Opens ConfirmDialog.
  - Title: "Cancel this engagement?"
  - Message: "This will permanently cancel this engagement and {N} open tasks. This action cannot be undone."
  - confirmLabel: "Cancel Engagement"
  - variant: "danger"

### Component API Details

#### Tabs

```svelte
<Tabs
  tabs={[
    { id: 'overview', label: 'Overview' },
    { id: 'engagements', label: 'Engagements', count: 4 },
    { id: 'tasks', label: 'Tasks', count: 12 }
  ]}
  activeTab="overview"
  onTabChange={(tabId) => activeTab = tabId}
/>
```

- Renders a horizontal tab bar as a `<nav>` with `role="tablist"`
- Each tab is a `<button>` with `role="tab"`, `aria-selected`
- Active tab: `text-blue-600 font-semibold border-b-2 border-blue-600`
- Inactive tab: `text-gray-500 font-normal hover:text-gray-700`
- Count badge: `text-gray-400` in parentheses after label
- Full-width bottom border: `border-b border-gray-200`
- Keyboard navigation: Arrow keys move focus between tabs, Enter/Space activates

#### Select

```svelte
<Select
  options={[
    { value: 'ACTIVE', label: 'Active' },
    { value: 'INACTIVE', label: 'Inactive' }
  ]}
  value={selectedStatus}
  onSelect={(val) => selectedStatus = val}
  placeholder="All statuses"
/>
```

- Custom dropdown (not native `<select>`) for consistent styling
- Trigger: same styling as ClientPicker trigger (border, padding, chevron)
- Dropdown: `z-20`, `rounded-md`, `shadow-lg`, `border border-gray-200`, `bg-white`
- Options: `py-2 px-3`, hover `bg-gray-100`, selected shows `Check` icon
- Keyboard: Escape closes, Arrow keys navigate, Enter selects

#### GroupedSelect

```svelte
<GroupedSelect
  groups={[
    { label: 'GST', options: [
      { value: 'gst-return', label: 'GST Return Filing' },
      { value: 'gst-registration', label: 'GST Registration' }
    ]},
    { label: 'Income Tax', options: [...] }
  ]}
  value={selectedType}
  onSelect={(val) => selectedType = val}
  placeholder="Select engagement type"
/>
```

- Same base styling as Select, but options list includes group headers
- Group header: `text-xs font-semibold uppercase tracking-wider text-gray-400 px-3 py-1.5` -- not selectable
- Group divider: `border-t border-gray-100 my-1` between groups (not before first)
- Search built in: input at top of dropdown (same as ClientPicker pattern)

#### InlineEdit

```svelte
<InlineEdit
  value={client.contactPerson}
  onSave={async (newVal) => { await updateClient({ contactPerson: newVal }) }}
  type="text"
/>
```

- **Display mode**: Shows value as plain text. On hover, shows subtle `gray-100` background and `Pencil` icon (14px, `gray-400`) at right
- **Edit mode**: Replaces text with Input component. Auto-focuses. Enter saves (calls `onSave`), Escape cancels
- **Saving state**: Shows small spinner (14px) replacing the pencil icon
- **Error state**: If `onSave` throws, reverts to display mode and triggers toast error
- **Empty value**: Shows `--` in `gray-400`, still editable on click

#### StatusTransitionDropdown

```svelte
<StatusTransitionDropdown
  currentStatus="ACTIVE"
  transitions={ENGAGEMENT_STATUS_TRANSITIONS}
  onTransition={(newStatus) => handleStatusChange(newStatus)}
  entityType="engagement"
/>
```

- Trigger: Renders current status as StatusBadge + small `ChevronDown` icon
- Dropdown: Shows only valid target statuses as StatusBadge items
- On select: Calls `onTransition` with the new status value. The parent component handles confirmation dialogs for COMPLETED/CANCELLED

## Interaction Contracts

### Client List Search & Filter

- **Search**: Input with `Search` icon. Debounced 300ms. Sends `search` query param to API. Clears on "Clear filters" action.
- **Filters**: Each filter updates URL query params. Changing any filter resets to page 1. All filters are optional (show "All" as default selected option). Filters persist in URL for shareability.
- **Filter bar responsive**: On mobile (< 768px), filters stack vertically in a single column. On desktop, horizontal flex row with `flex-wrap` for overflow.
- **URL sync**: `?search=acme&status=ACTIVE&page=2` pattern. SvelteKit `$page.url.searchParams` drives filter state. Back/forward navigation restores filter state.

### Client Form Validation

- **On blur**: Each field validates individually. PAN/TAN/CIN/GSTIN use shared REGEX. Required fields show error on blur if empty.
- **On submit**: All fields validated. If errors exist, scroll to first error field, focus it. Show generic toast "Please fix the errors below and try again."
- **Server errors**: 409 conflict (display_name) caught from API response, shown as field error under display_name input AND as toast. Other server errors shown as toast only.
- **Submit button**: Disabled while submitting. Shows spinner + "Creating..." / "Saving..." text.

### Inline Edit (Client Detail)

- **Trigger**: Hover shows edit affordance (pencil icon + subtle bg change). Click enters edit mode.
- **Edit mode**: Input appears in place, auto-focused, pre-filled with current value.
- **Save**: Enter key or blur triggers save. API call fires. Spinner shows during save.
- **Cancel**: Escape key reverts to display mode without saving.
- **Optimistic**: Value updates immediately on save trigger. If API fails, reverts and shows toast error.
- **Concurrent edits**: Only one field editable at a time. Clicking another field saves the current one first (via blur).

### Tab Navigation (Client Detail)

- **URL sync**: Active tab reflected in URL query param: `?tab=overview`, `?tab=engagements`, `?tab=tasks`. Default: `overview`.
- **Data loading**: Each tab loads its data on activation (lazy). Overview data loaded on initial page load (SSR). Engagements and Tasks tabs fetch on first activation, then cache.
- **Tab persistence**: Switching tabs updates URL without full page reload. Back button returns to previous tab.

### Engagement Create Modal

- **Open**: Modal opens with animation (Phase 3 Modal spec: fade overlay 150ms + scale content 200ms).
- **Client pre-fill**: When opened from client detail, ClientPicker is pre-filled and shown as read-only text (not a disabled picker). Shows client name with a small "x" to clear and pick a different client.
- **Template preview fetch**: When engagement type is selected AND auto_create_tasks is checked, fetch template via `GET /api/engagement-types/:id/template`. Show loading skeleton (3 lines) during fetch. Cache result per engagement type for the modal session.
- **Template preview toggle**: Animate open/close with height transition (200ms ease-in-out). Content fades in (150ms).
- **More options toggle**: Same animation pattern. Collapsed by default. Toggle text changes: "More options" (collapsed) / "Fewer options" (expanded).
- **Submit**: Disable all inputs during submission. Button shows spinner + "Creating...". On success: close modal, show toast, invalidate page data. On error: show toast, re-enable form.

### GST Number Management

- **Add**: "Add GST" button opens GstNumberModal in create mode. On success: toast + refresh GST table.
- **Edit**: Pencil icon on row opens GstNumberModal in edit mode with pre-filled data. On success: toast + refresh.
- **Delete**: Trash icon opens ConfirmDialog. On confirm: API call, toast "GST number removed.", refresh table.
- **Set as Primary**: Clicking "Set Primary" on a non-primary row immediately fires API call. Shows spinner on the row during the call. On success: toast + refresh (new primary highlighted, old primary un-highlighted).

### DataTable Interaction (Common to all tables)

All DataTables in Phase 4 use server-side pagination mode (Phase 3 DataTable with `totalItems` + `onPageChange` + `onSort` props).

- **Sort**: Click sortable column header. First click: ascending. Second click: descending. Third click: remove sort. Fires `onSort` callback which updates URL params and triggers server fetch.
- **Page change**: Fires `onPageChange` callback. Updates `page` URL param.
- **Page size**: Dropdown in pagination bar. Updates `limit` URL param. Resets to page 1.
- **Loading between page/sort/filter changes**: DataTable shows LoadingSkeleton (replaces table body only, header remains). This avoids a flash of empty state.
